Apa Itu Commit pada Git?

Lebih dari sekadar titik simpan biasa—sebuah commit adalah kapsul waktu kriptografis yang merekam keadaan utuh (snapshot) seluruh proyek Anda pada satu titik waktu, terikat secara permanen dalam rantai riwayat yang tidak dapat dipalsukan.

LAPISAN 01 // IDENTITAS KRIPTOGRAFIS

SHA-1 / SHA-256 Checksum Hash

Setiap commit tidak dinamai dengan angka urut (1, 2, 3), melainkan dikalkulasi menggunakan fungsi hash kriptografis dari seluruh isi file, struktur direktori, dan riwayat sebelumnya. Jika satu titik koma saja diubah di dalam kode, hash ini akan berubah total—menjamin integritas mutlak tanpa risiko manipulasi diam-diam.

PIPELINE WORKFLOW

Bagaimana File Bertransformasi Menjadi Commit?

Git memisahkan area kerja menjadi tiga ruang isolasi agar Anda dapat menyusun atomic commit yang presisi sebelum menguncinya ke dalam riwayat repositori.

STAGE 01 Modified
Working Directory

Ruang pasir lokal di mana Anda menulis, memodifikasi, atau menghapus kode secara bebas di editor (VS Code) tanpa memengaruhi riwayat Git.

index.html (untracked/modified)
git add
STAGE 02 Staged
Staging Area (Index)

Ruang kurasi tempat Anda memilih secara spesifik perubahan mana saja yang layak masuk ke dalam satu paket snapshot logis berikutnya.

.git/index (siap dibungkus)
git commit
STAGE 03 Immutable
Local Repository (.git)

Keadaan di Staging Area dibekukan secara permanen menjadi objek commit ber-hash SHA-1 dan diikat ke cabang aktif Anda.

HEAD -> branch-rheza [4f9a8c2]

PILLAR // 01

Snapshot Utuh, Bukan Sekadar Selisih (Diff)

Berbeda dengan sistem versi lama yang hanya menyimpan daftar baris yang berubah (delta-based), setiap commit di Git memotret kondisi seluruh file proyek. Untuk file yang tidak berubah, Git cukup membuat tautan referensi (pointer) ke file lama sehingga sangat cepat dan hemat memori.

DATA MODEL Directed Acyclic Graph (DAG)
+ +
PILLAR // 02

Immutability & Jaminan Anti-Korupsi Data

Karena setiap commit mengunci hash dari commit induknya (parent), struktur riwayat bekerja menyerupai Merkle Tree. Tidak ada satu pun anggota tim yang dapat mengubah riwayat masa lalu tanpa mengubah hash seluruh commit setelahnya.

VERIFICATION SHA-1 / SHA-256 Checksum
+ +
PILLAR // 03

Fondasi Isolasi Branch & Kolaborasi Tim

Branch di Git sejatinya hanyalah sebuah penunjuk ringan (lightweight movable pointer) yang mengarah ke satu commit spesifik. Hal ini memungkinkan 5 kolaborator bekerja di branch masing-masing secara simultan tanpa menduplikasi folder proyek.

BRANCH OVERHEAD 41 Bytes Pointer File
+ +
PILLAR // 04

Atomic Commit & Mesin Waktu (Time-Travel)

Dengan disiplin Atomic Commit (satu commit untuk satu perubahan logis) dan Conventional Commits, tim dapat membaca kronologi arsitektur dengan jelas, melacak sumber bug secara instan (git bisect), atau melakukan git revert dengan aman.
